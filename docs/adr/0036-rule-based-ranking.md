# Java ranks candidates; the model leaves the generate path

Generate and re-plan order candidates with the same Java comparator the horizon uses: ranking group, then inherited due date (undated last), then priority, then id, followed by dependency-order repair. This supersedes [ADR 0006](0006-ai-total-ordering.md) and [ADR 0022](0022-bound-ai-ranking-requests.md). The prompt it replaces was already a comparator written in English, Java already validated and repaired the result, and its order (priority before due date) disagreed with the horizon's (due date before priority), so a forecast could contradict the plan. One function removes that gap, makes generation deterministic and free of provider failures, and lets the app plan without an API key. The accepted cost is that an undated HIGH task sorts after dated LOW tasks in its group, and the model can no longer use descriptions to break ties; the model is instead used on text that rules cannot read, starting with estimate suggestions. `PLAN_CANDIDATE_LIMIT` stays at 100 for now. Plans saved under the old ranking are not rewritten.
