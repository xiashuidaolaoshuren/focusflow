# One Daily plan per owner and date

A Daily plan is now a schedule for a calendar day, not one of several ranking suggestions. FocusFlow enforces a unique `(owner, planning date)` and reads it through `GET /api/daily-plans/by-date`. Generation uses compare-and-replace: no current plan plus no `replacePlanId` creates; a current plan plus no id returns `PLAN_EXISTS`; a matching id replaces; every stale or vanished target returns `PLAN_CHANGED`. Replacement atomically deletes the old plan and creates a new identity, so `replacePlanId` is the concurrency token and old detail URLs are stale. Plan create, replace, and delete take the shared owner scheduling lock; generation rechecks its matrix inside that short transaction so concurrent requests cannot bypass confirmation or uniqueness. Accumulating rows made sense for disposable orderings; versioning would complicate 1.3.0 actuals. That milestone must further protect plans once actuals exist.
